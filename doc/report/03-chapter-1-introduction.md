# บทที่ 1 บทนำ

> เนื้อหาพร้อมใช้ — ระยะเวลาโครงงานในหัวข้อ 1.6 ระบุชัดเจนแล้ว (ภาคเรียนที่ 1/2568 และ 2/2568-2569)

## 1.1 ที่มาและความสำคัญของปัญหา

ปัจจุบัน ธุรกิจร้านอาหารในประเทศไทยมีอัตราการเติบโตอย่างต่อเนื่องและมีการแข่งขันสูง ผู้ประกอบการต่างมุ่งหาเครื่องมือที่ช่วยเพิ่มประสิทธิภาพในการดำเนินงาน โดยระบบ ณ จุดขาย (Point of Sale หรือ POS) ถือเป็นหนึ่งในเครื่องมือที่ได้รับความนิยมอย่างกว้างขวาง ในประเทศไทยมีระบบ POS สำหรับร้านอาหารหลายราย เช่น FoodStory ซึ่งเป็นระบบที่มีประสบการณ์ในตลาดมากกว่าหนึ่งทศวรรษ และ Wongnai POS หรือ LINE MAN POS ที่ครองส่วนแบ่งการตลาดประมาณร้อยละ 40 ของระบบ POS ในธุรกิจร้านอาหาร โดยระบบเหล่านี้มีฟังก์ชันครอบคลุมการบริหารร้าน เช่น การจัดการเมนู คลังสินค้า สมาชิก และการเชื่อมต่อบริการ Delivery อย่างไรก็ตาม ระบบเหล่านี้ส่วนใหญ่ให้บริการในรูปแบบซอฟต์แวร์เช่าใช้ (Software-as-a-Service หรือ SaaS) ที่ผู้ใช้งานต้องเสียค่าใช้จ่ายรายเดือนอย่างต่อเนื่อง และไม่สามารถปรับแต่งระบบให้ตรงกับโครงสร้างการดำเนินงานเฉพาะของแต่ละร้านได้

จากการศึกษาสภาพการดำเนินงานของร้านอาหารในปัจจุบัน รวมถึงประสบการณ์ของคณะผู้จัดทำที่เคยทำงานในร้านอาหารและการสังเกตการณ์ขณะใช้บริการในร้านต่าง ๆ พบว่าร้านอาหารจำนวนมากยังคงประสบปัญหาในกระบวนการให้บริการลูกค้าหลายประการ ได้แก่ ลูกค้าต้องรอเป็นเวลานานเพื่อเรียกพนักงานมาจดเมนู พนักงานยังคงใช้กระดาษในการจดออเดอร์ซึ่งทำให้พนักงานครัวอ่านลายมือไม่ออกหรือตกหล่นรายการอาหาร การตรวจสอบสลิปการโอนเงินด้วยตาเปล่าทำให้เกิดความล่าช้าและพลาดได้ง่าย การแยกบิลของลูกค้ากลุ่มใหญ่ต้องอาศัยการคำนวณด้วยมือซึ่งมีความซับซ้อน รวมถึงระบบ POS เดิมที่ใช้อยู่ส่วนใหญ่มีค่าใช้จ่ายสูงและไม่ยืดหยุ่นต่อการปรับเปลี่ยนตามความต้องการเฉพาะของร้าน ซึ่งข้อจำกัดเหล่านี้ส่งผลให้ประสิทธิภาพในการดำเนินงานลดลงและกระทบต่อประสบการณ์ของลูกค้าโดยตรง

ด้วยเหตุผลที่กล่าวมาข้างต้น คณะผู้จัดทำจึงเห็นความสำคัญในการออกแบบและพัฒนา "ระบบบริหารธุรกิจร้านอาหารผ่านเว็บพร้อมระบบ POS (Restaurant Business Web Management System with POS หรือ RBMS-POS)" ขึ้น เพื่อยกระดับการบริหารธุรกิจร้านอาหารด้วยการนำเทคโนโลยีเว็บแอปพลิเคชันสมัยใหม่มาประยุกต์ใช้ ความสำคัญของโครงงานนี้คือการรวมฟังก์ชันที่จำเป็นต่อการดำเนินงานร้านอาหารไว้ในระบบเดียวกัน ประกอบด้วยการสั่งอาหารด้วยตนเองของลูกค้าผ่านการสแกนรหัสคิวอาร์ (QR Code) ที่โต๊ะ การสื่อสารข้อมูลแบบเวลาจริง (Real-time) ระหว่างหน้าร้าน ครัว และลูกค้าผ่านเทคโนโลยี SignalR การตรวจสอบสลิปการโอนเงินอัตโนมัติด้วยระบบรู้จำตัวอักษรด้วยภาพ (Optical Character Recognition หรือ OCR) และระบบสิทธิ์การเข้าถึงตามตำแหน่งงานแบบไดนามิก (Role-Based Access Control) ที่สามารถปรับให้สอดคล้องกับโครงสร้างพนักงานของแต่ละร้านได้ ทั้งนี้ ระบบได้รับการพัฒนาในรูปแบบโครงการรหัสเปิด (Open Source) เพื่อเปิดโอกาสให้ผู้สนใจสามารถนำไปติดตั้งใช้งานหรือต่อยอดได้อย่างเสรี โดยให้ความสำคัญกับความเสถียรของระบบเป็นหลัก เพื่อให้สามารถรองรับการใช้งานในช่วงเวลาที่มีปริมาณการสั่งอาหารหนาแน่นได้อย่างต่อเนื่อง ซึ่งฟังก์ชันเหล่านี้จะช่วยให้ผู้ประกอบการสามารถบริหารร้านได้อย่างมีประสิทธิภาพและลดปัญหาที่เกิดขึ้นในกระบวนการให้บริการลูกค้า

## 1.2 วัตถุประสงค์ของโครงงาน

1.2.1 เพื่อพัฒนาระบบบริหารจัดการร้านอาหารแบบครบวงจรในรูปแบบเว็บแอปพลิเคชัน ที่รองรับการทำงานของผู้ดูแลระบบ พนักงาน และลูกค้าภายในระบบเดียวกัน

1.2.2 เพื่ออำนวยความสะดวกในการสั่งอาหารของลูกค้าผ่านการสแกน QR Code ที่โต๊ะ โดยลูกค้าสามารถสั่งอาหารและขอชำระเงินได้ด้วยตนเอง ลดการพึ่งพาพนักงานในการรับออเดอร์

1.2.3 เพื่อพัฒนาระบบสื่อสารแบบเวลาจริงระหว่างหน้าร้านและครัว ด้วยหน้าจอแสดงรายการอาหาร (Kitchen Display) ที่ทำงานผ่าน SignalR สำหรับลดความผิดพลาดในการส่งออเดอร์และการเสิร์ฟ

1.2.4 เพื่อพัฒนาระบบตรวจสอบสลิปการโอนเงินอัตโนมัติด้วย OCR ที่สามารถอ่านยอดเงินและเปรียบเทียบกับยอดที่ต้องชำระ เพื่อเพิ่มความรวดเร็วและความถูกต้องในกระบวนการรับชำระเงิน

1.2.5 เพื่อพัฒนาระบบสิทธิ์การเข้าถึงตามตำแหน่งงานแบบไดนามิก (Role-Based Access Control) ที่สามารถปรับให้สอดคล้องกับโครงสร้างพนักงานของแต่ละร้านได้โดยไม่ต้องแก้ไขโปรแกรม

## 1.3 สมมติฐานของโครงงาน

1.3.1 การพัฒนาระบบสั่งอาหารด้วยตนเองผ่าน QR Code จะช่วยลดเวลารอของลูกค้าและลดภาระงานของพนักงานเสิร์ฟได้อย่างมีนัยสำคัญ เมื่อเทียบกับการสั่งอาหารผ่านพนักงานในรูปแบบเดิมที่ต้องอาศัยการจดบันทึก

1.3.2 การมีระบบสื่อสารแบบเวลาจริงผ่าน SignalR ระหว่างหน้าร้าน ครัว และลูกค้า จะช่วยลดความผิดพลาดในการส่งออเดอร์และการตกหล่นของรายการอาหาร เมื่อเทียบกับระบบที่ใช้ใบออเดอร์กระดาษ

1.3.3 การนำระบบ OCR มาใช้ในการตรวจสอบสลิปการโอนเงิน จะช่วยเพิ่มความรวดเร็วและความถูกต้องในกระบวนการรับชำระเงิน เมื่อเทียบกับการตรวจสอบด้วยสายตาของพนักงาน

1.3.4 การออกแบบระบบสิทธิ์การเข้าถึงตามตำแหน่งงานแบบไดนามิก จะช่วยให้ระบบสามารถนำไปประยุกต์ใช้กับร้านอาหารที่มีโครงสร้างพนักงานแตกต่างกันได้อย่างยืดหยุ่น โดยไม่ต้องพัฒนาเพิ่มเติมในแต่ละรูปแบบของร้าน

## 1.4 ขอบเขตของโครงงาน

### 1.4.1 ขอบเขตด้านผู้ใช้งานระบบ

ระบบรองรับผู้ใช้งานตามหลักการ Use Case จำนวน 3 กลุ่มหลัก โดยกลุ่ม Staff สามารถแบ่งย่อยเป็นตำแหน่งงานต่าง ๆ ได้ตามโครงสร้างของแต่ละร้านผ่านระบบสิทธิ์การเข้าถึงแบบไดนามิก

1) **ผู้ดูแลระบบ (Admin)** — มีหน้าที่ตั้งค่าระบบ จัดการเมนู ตำแหน่งงาน พนักงาน โต๊ะ ผังร้าน รวมถึงการเรียกดูรายงาน Dashboard

2) **พนักงาน (Staff)** — มีหน้าที่ในการดำเนินงานหน้าร้านและหลังร้าน ซึ่งสามารถแบ่งย่อยเป็นตำแหน่งงานต่าง ๆ ตามความต้องการของร้าน เช่น พนักงานเสริฟ พนักงานครัว แคชเชียร์ ผู้จัดการสาขา โดยแต่ละตำแหน่งสามารถกำหนดสิทธิ์การเข้าถึงเมนูและฟังก์ชันได้อย่างยืดหยุ่น

3) **ลูกค้า (Customer)** — ใช้งานผ่าน Mobile Web หลังการสแกน QR Code ที่โต๊ะ สามารถสั่งอาหาร เรียกพนักงาน และขอชำระเงินได้ด้วยตนเอง

### 1.4.2 ขอบเขตด้านการทำงานของระบบ

1.4.2.1 ระบบสามารถจัดการเมนูอาหารและเครื่องดื่มได้อย่างยืดหยุ่น โดยรองรับการเพิ่ม แก้ไข และลบรายการเมนู พร้อมกำหนดหมวดหมู่ ราคาขาย ภาพประกอบเมนู สถานะการเปิด-ปิดการขาย และรายละเอียดอื่น ๆ เพื่อให้แสดงผลในหน้าจอสั่งอาหารของลูกค้าได้แบบเวลาจริง

1.4.2.2 ระบบสามารถจัดการโต๊ะอาหารและผังพื้นที่นั่งในร้านได้ โดยรองรับการเพิ่ม แก้ไข และลบรายการโต๊ะ การกำหนดหมายเลขโต๊ะ โซน จำนวนลูกค้าที่นั่ง และสถานะของโต๊ะ (Available / Occupied / Reserved) พร้อมเชื่อมโยงกับคำสั่งซื้อของลูกค้าในระบบได้โดยอัตโนมัติ

1.4.2.3 ระบบสามารถแสดงรายการออเดอร์ที่ลูกค้าสั่งเข้ามาแบบเวลาจริง พร้อมการจัดการสถานะของออเดอร์ และรองรับการแก้ไขหรือยกเลิกออเดอร์ตามสิทธิ์ของพนักงานที่ได้รับการกำหนดไว้

1.4.2.4 ระบบสามารถรองรับการจัดการออเดอร์ได้จากหลายช่องทาง ทั้งจากพนักงานภายในร้านและจากลูกค้าผ่านการสแกน QR Code บนโต๊ะ โดยทุกคำสั่งซื้อจะถูกส่งต่อไปยังหน้าจอแสดงรายการอาหาร (Kitchen Display) แยกตามประเภทเมนู ทั้งอาหาร เครื่องดื่ม และของหวาน เพื่อให้พนักงานในแต่ละส่วนสามารถเตรียมรายการได้อย่างถูกต้อง

1.4.2.5 ระบบสามารถแสดงรายการอาหาร เครื่องดื่ม และของหวานในหน้าจอแสดงรายการอาหารแยกตามประเภทเมนูได้ ซึ่งจะช่วยให้พนักงานในแต่ละส่วนสามารถจัดการออเดอร์ของตนเองได้อย่างชัดเจน พร้อมรองรับการปรับสถานะของรายการอาหาร เช่น "กำลังทำ" และ "เสร็จแล้ว"

1.4.2.6 ระบบสามารถจัดการการชำระเงินได้ โดยรองรับทั้งการชำระเงินสดและการชำระผ่านการสแกน QR Code พร้อมเชื่อมต่อกับรายการออเดอร์ของแต่ละโต๊ะ ซึ่งลูกค้าและพนักงานสามารถตรวจสอบรายการออเดอร์ก่อนการยืนยันชำระเงินได้

1.4.2.7 ระบบสามารถให้ลูกค้าสแกน QR Code บนโต๊ะผ่านสมาร์ตโฟน เพื่อเข้าสู่หน้าสั่งอาหาร เลือกเมนูพร้อมระบุตัวเลือกเพิ่มเติม และส่งออเดอร์เข้าสู่ระบบกลาง พร้อมรองรับการตรวจสอบรายการสั่งและติดตามสถานะออเดอร์แบบเวลาจริงจนเสร็จสิ้นการให้บริการ โดยระบบจะผูกหมายเลขโต๊ะกับออเดอร์ได้โดยอัตโนมัติ และมีฟังก์ชันปุ่มเรียกพนักงานและปุ่มขอชำระเงินเพื่ออำนวยความสะดวกแก่ลูกค้า

1.4.2.8 ระบบรองรับการบริหารจัดการพนักงาน โดยสามารถเพิ่ม แก้ไข ลบ และจัดกลุ่มพนักงานภายในร้านตามหน้าที่ได้ พร้อมทั้งสามารถตั้งค่าบัญชีผู้ใช้และรหัสผ่านส่วนตัวเพื่อใช้สำหรับการเข้าสู่ระบบ

1.4.2.9 ระบบสามารถกำหนดค่าเริ่มต้นและข้อมูลพื้นฐานที่จำเป็น เช่น ภาษีมูลค่าเพิ่ม (VAT) และค่าบริการ (Service Charge) พร้อมกำหนดสิทธิ์การเข้าถึงตามตำแหน่งงาน (Role-Based Access Control) ให้แต่ละบทบาทสามารถเข้าถึงได้เฉพาะโมดูลหรือฟังก์ชันที่เกี่ยวข้องกับหน้าที่ของตน

1.4.2.10 ระบบสามารถแสดงรายงานสรุปยอดขาย เช่น ยอดขายต่อวัน ต่อเดือน และต่อปี พร้อมข้อมูลจำนวนลูกค้ารวมต่อวัน รวมถึงการแสดงเมนูอาหารและเครื่องดื่มที่มียอดขายสูงสุดในแต่ละหมวด เพื่อสนับสนุนการวิเคราะห์และการวางแผนธุรกิจของเจ้าของร้าน

### 1.4.3 ขอบเขตด้านเครื่องมือและเทคโนโลยีที่ใช้ในการพัฒนา

1) **เครื่องมือพัฒนาส่วนแสดงผล (Front-end)**: พัฒนาเว็บแอปพลิเคชันด้วยเฟรมเวิร์ก Angular 19.1 ตกแต่งรูปแบบหน้าเว็บไซต์ด้วย Tailwind CSS 3.4 และใช้คอมโพเนนต์สำเร็จรูปจาก PrimeNG

2) **เครื่องมือพัฒนาส่วนหลังบ้าน (Back-end)**: พัฒนา Web API ด้วย ASP.NET Core 9.0 ในภาษา C# และใช้ SignalR สำหรับการสื่อสารแบบ Real-time ผ่าน WebSocket

3) **เครื่องมือจัดการฐานข้อมูล (Database)**: ใช้ SQL Server เป็นระบบฐานข้อมูลเชิงสัมพันธ์ และใช้ Entity Framework Core 9 เป็นเครื่องมือเชื่อมต่อในรูปแบบอ็อบเจกต์เชิงสัมพันธ์ (ORM)

4) **เครื่องมือจัดการระบบยืนยันตัวตน (Authentication)**: ใช้ JSON Web Token (JWT) ร่วมกับ Refresh Token สำหรับการจัดการ Session และเข้ารหัสรหัสผ่านด้วย BCrypt

5) **เครื่องมือจัดเก็บไฟล์ (File Storage)**: ใช้ MinIO ซึ่งเป็น Object Storage แบบ Self-hosted ที่ใช้ API เทียบเท่า Amazon S3

6) **เครื่องมือ Container**: ใช้ Docker และ Docker Compose สำหรับจัดการ Dependencies ในการพัฒนาและ Deploy

7) **เครื่องมือเอกสาร API**: ใช้ Swagger / OpenAPI สำหรับสร้างเอกสาร API และ ng-openapi-gen สำหรับสร้าง TypeScript Client โดยอัตโนมัติ

## 1.5 ประโยชน์ที่คาดว่าจะได้รับ

1.5.1 ลูกค้าได้รับประสบการณ์การใช้บริการที่สะดวกและคล่องตัวมากขึ้น โดยสามารถเลือกเมนูในจังหวะของตนเอง ติดตามสถานะของรายการอาหารตลอดการให้บริการ และเรียกพนักงานหรือขอชำระเงินผ่านระบบได้โดยไม่ต้องรอจังหวะที่พนักงานว่าง

1.5.2 พนักงานหน้าร้านและพนักงานครัวสามารถปฏิบัติงานได้อย่างเป็นระบบมากขึ้น โดยลดการพึ่งพาเอกสารกระดาษและการสื่อสารด้วยปากต่อปาก ทำให้กระบวนการรับออเดอร์และส่งรายการอาหารไปยังครัวเป็นไปอย่างต่อเนื่อง แม้ในช่วงเวลาที่มีปริมาณลูกค้าหนาแน่น

1.5.3 พนักงานแคชเชียร์สามารถปฏิบัติหน้าที่ในการรับชำระเงินและการปิดยอดประจำวันได้สะดวกขึ้น ด้วยระบบเซสชันแคชเชียร์ (Cashier Session) ที่ตรวจสอบยอดเงินสดในลิ้นชักทุกกะการทำงาน ช่วยลดความเสี่ยงจากความผิดพลาดในการนับเงินและการตรวจสอบรายการชำระเงิน

1.5.4 เจ้าของร้านและผู้จัดการสามารถบริหารการดำเนินงานของร้านได้จากระบบเดียว ตั้งแต่การจัดการเมนู โต๊ะ พนักงาน และการตั้งค่าค่าบริการ ไปจนถึงการเรียกดูรายงานสรุปยอดขายแบบเวลาจริง เพื่อใช้เป็นข้อมูลประกอบการตัดสินใจในการดำเนินธุรกิจ

1.5.5 เจ้าของร้านสามารถลดค่าใช้จ่ายในการใช้ซอฟต์แวร์ในระยะยาวได้ เนื่องจากระบบได้รับการพัฒนาในรูปแบบโครงการรหัสเปิด (Open Source) ที่สามารถติดตั้งบนเครื่องเซิร์ฟเวอร์ของร้านได้โดยตรง โดยไม่ต้องเสียค่าบริการรายเดือนเช่นเดียวกับระบบ POS ที่ให้บริการในรูปแบบ SaaS

1.5.6 ระบบเป็นแนวทางในการพัฒนาเว็บแอปพลิเคชันสำหรับธุรกิจร้านอาหารขนาดเล็กและขนาดกลาง ที่ผู้สนใจสามารถนำสถาปัตยกรรมและเทคโนโลยีที่ใช้ในการพัฒนาไปประยุกต์ใช้กับระบบของตนเอง หรือต่อยอดเพื่อใช้งานในเชิงพาณิชย์ในอนาคตได้

## 1.6 ขั้นตอนการดำเนินงาน

### 1.6.1 ศึกษาและรวบรวมข้อมูล (เดือนกรกฎาคม พ.ศ. 2568)

ศึกษาปัญหาและรวบรวมความต้องการของระบบจากประสบการณ์การทำงานพาร์ทไทม์ในร้านอาหารของคณะผู้จัดทำ ร่วมกับการสำรวจระบบ POS ในตลาด ได้แก่ FoodStory และ LINE MAN Wongnai POS เพื่อทำความเข้าใจฟังก์ชันการทำงานหลักและจุดที่สามารถพัฒนาให้ดีกว่าได้ พร้อมทั้งศึกษาค้นคว้าเครื่องมือและเทคโนโลยีที่เลือกใช้ในการพัฒนาระบบตามที่ระบุไว้ในหัวข้อ 1.4.3

### 1.6.2 วิเคราะห์และออกแบบระบบ (เดือนสิงหาคม – เดือนกันยายน พ.ศ. 2568)

นำข้อมูลที่ได้จากการศึกษามาวิเคราะห์และออกแบบโครงสร้างของระบบ ครอบคลุมการกำหนดขอบเขตของโมดูลธุรกิจ สถาปัตยกรรมระบบ การออกแบบฐานข้อมูล ผังงานของกระบวนการทำงานหลัก และเครื่องสถานะ (State Machine) ของรายการอาหารและโต๊ะ โดยรายละเอียดของผลการออกแบบแสดงไว้ในบทที่ 3

### 1.6.3 พัฒนาระบบ (เดือนกันยายน พ.ศ. 2568 – เดือนมกราคม พ.ศ. 2569)

ดำเนินการเขียนโปรแกรมตามที่ได้ออกแบบไว้ในขั้นตอนที่ 1.6.2 โดยขั้นตอนนี้มีระยะทับซ้อนกับขั้นตอนการออกแบบในเดือนกันยายน พ.ศ. 2568 เพื่อให้สามารถพัฒนาส่วนที่ออกแบบเสร็จก่อนได้ทันที การพัฒนาแบ่งออกเป็นส่วนแสดงผล (Front-end) ทั้งสำหรับพนักงานในร้านและสำหรับลูกค้าผ่านมือถือ และส่วนหลังบ้าน (Back-end) ที่ครอบคลุม Web API ทั้ง 8 โมดูลธุรกิจ ระบบยืนยันตัวตน การสื่อสารแบบเวลาจริง และการเชื่อมต่อกับระบบจัดเก็บไฟล์

### 1.6.4 ทดสอบการทำงานและปรับปรุงแก้ไข (เดือนกุมภาพันธ์ พ.ศ. 2569)

นำระบบที่พัฒนาเสร็จมาทดสอบการทำงานในสภาพแวดล้อมจำลองโดยทีมผู้จัดทำ ทั้งบนเครื่องคอมพิวเตอร์ส่วนบุคคล (PC) และอุปกรณ์เคลื่อนที่ (Mobile) ครอบคลุมการใช้งานของผู้ใช้ทั้ง 3 บทบาท จากนั้นดำเนินการปรับปรุงแก้ไขข้อผิดพลาด (Bug) ที่พบ พร้อมทั้งทดสอบการนำระบบไปติดตั้ง (Deployment) บนเครื่องเซิร์ฟเวอร์ของสถาบันด้วย Docker เพื่อให้ระบบมีความพร้อมใช้งานในสภาพแวดล้อมที่ใกล้เคียงกับการใช้งานจริง

### 1.6.5 จัดทำเอกสารและนำเสนอผลงาน (เดือนกุมภาพันธ์ – เดือนมีนาคม พ.ศ. 2569)

รวบรวมผลการดำเนินงานตลอดทุกขั้นตอนมาจัดทำเป็นเอกสารปริญญานิพนธ์ฉบับสมบูรณ์ 5 บท พร้อมคู่มือการใช้งานระบบสำหรับผู้ใช้แต่ละบทบาท ขั้นตอนนี้ดำเนินงานคู่ขนานกับขั้นตอนที่ 1.6.4 ในเดือนกุมภาพันธ์ พ.ศ. 2569 เพื่อให้สามารถบันทึกผลการทดสอบเข้าสู่เอกสารได้ทันเหตุการณ์ ก่อนเตรียมความพร้อมสำหรับการนำเสนอผลงานต่อคณะกรรมการสอบในเดือนมีนาคม พ.ศ. 2569
