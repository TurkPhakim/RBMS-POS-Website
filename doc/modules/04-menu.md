# Module 4: Menu (จัดการเมนูอาหาร + หมวดหมู่ + ตัวเลือกเสริม)

> Master Data Module — เป็นแหล่งข้อมูลของ "สินค้า" ที่ระบบขาย — ทุกออเดอร์ดึงเมนูจาก Module นี้

---

## 1. Module นี้คืออะไร

ระบบจัดการรายการเมนูที่ร้านขาย รวมถึงหมวดหมู่ย่อย (Sub Category) และตัวเลือกเสริม (Option Group) ที่ลูกค้าเลือกเพิ่มได้ตอนสั่ง เช่น "ระดับความเผ็ด", "ความหวาน", "ท็อปปิ้ง"

ระบบแบ่งเมนูออกเป็น **3 ประเภทหลัก** (Category Type): **อาหาร (Food)** / **เครื่องดื่ม (Beverage)** / **ของหวาน (Dessert)** เพื่อแยกการจัดการและสิทธิ์ของพนักงานแต่ละแผนก

---

## 2. ช่วยธุรกิจร้านอาหารในเรื่องใด

| ปัญหาแบบดั้งเดิม | สิ่งที่ระบบนี้แก้ |
| --- | --- |
| เปลี่ยนราคาเมนู ต้องเปลี่ยนป้าย/เมนูกระดาษทุกใบ | แก้ที่เดียว → ทั้งระบบ (POS, Self-Order, ใบเสร็จ) เห็นราคาใหม่ทันที |
| ลูกค้าสั่งเมนูตัวเลือก (เผ็ดน้อย/หวานพิเศษ) → พนักงานต้องจดเอง อาจสื่อสารผิด | กำหนดตัวเลือกเสริมเป็นโครงสร้าง — ลูกค้าเลือกในระบบ ครัวเห็นชัดเจน |
| เมนูบางตัวขายเฉพาะช่วงเวลา (กลางวัน/เย็น) แต่ต้องแจ้งพนักงานเอง | กำหนดช่วงเวลาขาย (Period 1/2) → เมนูซ่อนใน Mobile Web อัตโนมัติ |
| เมนูเลิกขาย → ลูกค้าสั่งเสร็จแล้วต้องบอกขออภัย | ปิด IsAvailable → เมนูหายจากระบบทันที |
| ต้นทุนเมนูไม่บันทึก → คำนวณกำไรไม่ได้ | บันทึก CostPrice — Dashboard คำนวณกำไรขั้นต้นได้ |
| แพ้อาหารบางอย่าง ลูกค้าต้องถามพนักงานทุกครั้ง | บันทึก Allergens (สารก่อภูมิแพ้) — แสดงในเมนู Mobile Web |
| เมนูแนะนำ/เมนูยอดนิยม ไม่มีวิธีเน้น | IsPinned → ดันเมนูขึ้นบนสุดของรายการ |

**คุณค่าทางธุรกิจ**: เปลี่ยนราคา/เพิ่มเมนูได้ทันที + ลดความผิดพลาดในการสั่งอาหาร + รองรับเมนูตามฤดูกาล + คำนวณกำไรขั้นต้นได้

## 3. Business Logic หลัก

### 3.1 โครงสร้างเมนู 3 ระดับ

```
Category Type (แค่ enum — ไม่มีในตาราง)
  ├── Food (อาหาร)
  ├── Beverage (เครื่องดื่ม)
  └── Dessert (ของหวาน)
       │
       ▼
TbMenuSubCategory (หมวดหมู่ย่อย) — แยกตาม CategoryType
  ├── อาหาร: "ของทอด", "อาหารจานเดียว", "ก๋วยเตี๋ยว"
  ├── เครื่องดื่ม: "ชา-กาแฟ", "น้ำผลไม้", "เครื่องดื่มแอลกอฮอล์"
  └── ของหวาน: "ไอศกรีม", "เค้ก", "ผลไม้"
       │
       ▼
TbMenu (รายการเมนู)
  ├── ชื่อไทย, ชื่ออังกฤษ, คำอธิบาย
  ├── รูปภาพ (ImageFileId → S3)
  ├── ราคาขาย + ต้นทุน (CostPrice — สำหรับคำนวณกำไร)
  ├── สถานะการขาย: IsAvailable (เปิด/ปิดการขาย)
  ├── ช่วงเวลาขาย: IsAvailablePeriod1, IsAvailablePeriod2 (ตามเวลาทำการร้าน)
  ├── Tags: bit flags (Spicy / Cold / Hot / Recommended / NewItem / ฯลฯ)
  ├── Allergens: สารก่อภูมิแพ้ (เช่น "ถั่ว, นม, ไข่")
  ├── CaloriesPerServing: แคลอรี่/หน่วย
  └── IsPinned: ปักหมุดขึ้นบนสุด (เมนูแนะนำ)
       │
       ▼
TbMenuOptionGroup (เชื่อมเมนูกับกลุ่มตัวเลือก — M:M)
       │
       ▼
TbOptionGroup (กลุ่มตัวเลือก)
  ├── ชื่อกลุ่ม: "ระดับความเผ็ด", "ความหวาน", "ท็อปปิ้ง"
  ├── ประเภท Single Choice / Multiple Choice
  └── Required: บังคับเลือกหรือไม่
       │
       ▼
TbOptionItem (รายการในกลุ่ม)
  ├── ชื่อ: "เผ็ดน้อย", "หวานปกติ", "เพิ่มไข่ดาว"
  ├── PriceAdjustment: ราคาเพิ่ม/ลด (-10, 0, +20)
  └── CostPrice: ต้นทุนของตัวเลือกนั้น
```

### 3.2 กฎสำคัญ

1. **เมนูทุกตัวต้องอยู่ใน Sub Category** — ไม่มีเมนูลอย
2. **Sub Category ทุกตัวต้องอยู่ใน Category Type** — แบ่งเป็น 3 ประเภท (Food/Beverage/Dessert)
3. **สิทธิ์แยกตามประเภท** — มีสิทธิ์ `menu-food.create` ≠ `menu-beverage.create` → ครัวอาหารแก้เมนูเครื่องดื่มไม่ได้
4. **ลบ Sub Category ได้เฉพาะที่ไม่มีเมนูในนั้น** — ป้องกันเมนูค้าง
5. **เรียงลำดับ Sub Category ได้ (Drag & Drop)** — กำหนด SortOrder
6. **เมนูสามารถผูกได้หลาย Option Group** (M:M) — เช่น "ก๋วยเตี๋ยวต้มยำ" ผูกกับ "ระดับความเผ็ด" + "ขนาด"
7. **Option Group ใช้ร่วมกันหลายเมนูได้** — สร้างครั้งเดียวใช้กับทุกเมนูที่ขายเครื่องดื่ม
8. **Option ใช้ Hard Delete** — ลบทันทีเพราะไม่กระทบ Order เก่า (Order เก็บ snapshot ชื่อ+ราคาตอนสั่ง)
9. **ราคาขาย + ต้นทุนเป็น snapshot ตอนสั่ง** — แก้ราคาภายหลังไม่กระทบ Order เก่า (เก็บใน TbOrderItem.UnitPrice + CostPrice)
10. **ช่วงเวลาขาย 2 ช่วง** สอดคล้องกับเวลาทำการของร้าน (ดูที่ Shop Settings) → เมนูเช้า/บ่าย/เย็น

### 3.3 Tags (Bit Flags — `EMenuTag`)

| Bit | Tag | ความหมาย |
| :---: | --- | --- |
| 1 | Recommended | แนะนำ |
| 2 | Seasonal | เมนูตามฤดูกาล |
| 4 | SlowPreparation | เตรียมอาหารนาน (แจ้งลูกค้าให้รอ) |

> ใช้ bit flags เพื่อให้เมนู 1 ตัวมีหลาย tags พร้อมกัน (เช่น Recommended + Seasonal)
> **หมายเหตุ**: ระบบไม่ได้แยก "เผ็ด/เย็น/ร้อน" เป็น tag — ใช้ Allergens หรือคำอธิบายเมนูแทน

## 4. Workflow การทำงานจริง

### Workflow A — เปิดร้านครั้งแรก (Setup เมนู)

```
1. /menu/categories → กด "เพิ่มหมวดหมู่"
   ─ เลือก Category Type: "อาหาร"
   ─ ชื่อหมวด: "ของทอด" → บันทึก
   ─ ทำซ้ำสำหรับ "อาหารจานเดียว", "ก๋วยเตี๋ยว" ฯลฯ
2. /menu/options → กด "เพิ่มกลุ่มตัวเลือก"
   ─ ชื่อ: "ระดับความเผ็ด"
   ─ เพิ่มรายการ: "ไม่เผ็ด" (+0), "เผ็ดน้อย" (+0), "เผ็ดกลาง" (+0), "เผ็ดมาก" (+0)
   ─ บันทึก
3. /menu/food → กด "เพิ่มเมนูอาหาร"
   ─ ชื่อ: "ผัดกระเพราหมูสับไข่ดาว"
   ─ อัพโหลดรูป (S3) → ราคา 65 บาท, ต้นทุน 25 บาท
   ─ Sub Category: "อาหารจานเดียว"
   ─ Tags: Recommended (แนะนำ)
   ─ Allergens: "ถั่วเหลือง, ไข่"
   ─ ช่วงเวลาขาย: เปิดทั้ง 2 ช่วง
   ─ เลือก Option Group: "ระดับความเผ็ด" → บันทึก
4. เมนูพร้อมขายผ่านทั้ง POS (พนักงานสั่งให้ลูกค้า) และ Self-Order (ลูกค้าสั่งเอง)
```

### Workflow B — เปลี่ยนราคาเมนู (มีผลทันที)

```
1. /menu/food → ค้นหา "ผัดกระเพรา" → กดแก้ไข
2. เปลี่ยนราคาจาก 65 → 70 บาท → บันทึก
3. ผลที่เกิดขึ้น:
   ─ POS ตอนสั่งใหม่ → เห็นราคา 70
   ─ Mobile Web ลูกค้า → เห็นราคา 70
   ─ Order เก่าที่สั่งไปแล้ว → ยังเห็นราคา 65 (snapshot)
   ─ ใบเสร็จ Order เก่า → 65, ใบเสร็จ Order ใหม่ → 70
```

### Workflow C — ปิดการขายเมนูชั่วคราว (เช่น ของหมด)

```
1. /menu/food → ค้นหาเมนู → ติ๊ก "ปิดการขาย" (IsAvailable = false)
2. ผลที่เกิดขึ้น:
   ─ Mobile Web ลูกค้า → เมนูหายจากรายการ
   ─ POS → เมนูยังแสดงแต่กดเลือกไม่ได้ (สีจาง)
   ─ ของหมดแล้ว → เปิดกลับมาเมื่อมีของ
```

### Workflow D — กำหนดช่วงเวลาขายเมนู

```
1. ตั้งค่าเวลาทำการที่ Shop Settings → จันทร์-ศุกร์: 11:00-14:00, 17:00-22:00
2. /menu/food → "ก๋วยเตี๋ยวเย็นตาโฟ"
   ─ ติ๊ก IsAvailablePeriod1 (ช่วงกลางวัน)
   ─ เอาติ๊ก IsAvailablePeriod2 (ช่วงเย็น) ออก
3. ผลใน Mobile Web:
   ─ ช่วง 11:00-14:00 → ลูกค้าเห็นเมนูนี้
   ─ ช่วง 17:00-22:00 → ลูกค้าไม่เห็นเมนูนี้
   ─ พนักงานยัง Manual override สั่งให้ได้จาก POS (ถ้าจำเป็น)
```

### Workflow E — เรียงลำดับหมวดหมู่ใหม่

```
1. /menu/categories → เห็นรายการหมวด
2. Drag หมวด "ของทอด" จากตำแหน่งที่ 3 ขึ้นมาที่ 1
3. Drop → ระบบเรียก API /menu/categories/sort-order ส่งลำดับใหม่
4. ผลที่ Mobile Web → ลูกค้าเห็น "ของทอด" ขึ้นบนสุดทันที
```

### Workflow F — สร้างเมนูแนะนำ (Pinned)

```
1. /menu/food → "ผัดไทกุ้งสด" → ติ๊ก IsPinned = true → บันทึก
2. ระบบบันทึก IsPinned = true
3. ฝั่ง Frontend สามารถนำ IsPinned ไป filter/highlight ในหน้าเมนูได้ (เช่น แสดงป้าย "แนะนำ" หรือ section พิเศษ)
```

> **หมายเหตุ**: ระบบจัดเก็บ IsPinned ใน DB แต่ MenuService.GetMenusAsync ไม่ได้ order by IsPinned โดย default — ฝั่ง Frontend ต้องจัดลำดับเอง หรือเพิ่มการ filter จาก API

## 5. ข้อดี

| ข้อดี | คำอธิบาย |
| --- | --- |
| **เปลี่ยนราคา/รายการ Real-time** | แก้ที่เดียว ระบบทั้งหมดอัพเดตทันที ไม่ต้องเปลี่ยนป้าย |
| **แยก 3 ประเภทอย่างชัดเจน** | สิทธิ์การแก้แยกตามแผนก (อาหาร/เครื่องดื่ม/ของหวาน) |
| **รองรับเมนูตามช่วงเวลา** | เมนูเช้า/บ่าย/เย็น แสดงในช่วงที่ถูกต้องเอง |
| **Option Group ใช้ซ้ำ** | สร้าง "ระดับความเผ็ด" ครั้งเดียว ผูกได้หลายเมนู — แก้ครั้งเดียวมีผลทุกที่ |
| **ราคา Snapshot ใน Order** | เปลี่ยนราคาเมนู → Order เก่ายังถูก ไม่กระทบงบประมาณลูกค้าที่จ่ายไปแล้ว |
| **บันทึกต้นทุน** | คำนวณกำไรขั้นต้นได้ผ่าน Dashboard |
| **Tags (Bit Flags)** | เมนู 1 ตัวมีหลาย tags ได้ (แนะนำ + เมนูตามฤดูกาล + เตรียมนาน) — ลูกค้า filter ใน Mobile Web ได้ |
| **Allergens** | แจ้งสารก่อภูมิแพ้ → ลดความเสี่ยงด้านสุขภาพ |
| **IsPinned (Flag)** | เก็บสถานะเมนูปักหมุด — Frontend นำไป highlight หรือจัดลำดับเอง |
| **Drag & Drop เรียงลำดับ** | จัดเรียงเมนูง่าย ไม่ต้องกรอกตัวเลข |

## 6. ข้อเสีย / ข้อจำกัด

| ข้อจำกัด | ผลกระทบ + วิธีรับมือ |
| --- | --- |
| **Category Type มีแค่ 3 (Fix Code)** | ถ้าร้านอยากเพิ่ม "เซ็ตเมนู" หรือ "เครื่องเคียง" → ต้องแก้ที่ระดับ enum + permission + UI |
| **ช่วงเวลาขายมีแค่ 2 ช่วง** | สอดคล้องกับ Operating Hours 2 ช่วง — ร้าน 3 ช่วงต่อวันรองรับไม่ได้ |
| **ไม่มีระบบ Variant** | ขนาดเมนูแยกได้ผ่าน Option Group เท่านั้น (เล็ก/กลาง/ใหญ่) — ไม่มี SKU แยก |
| **ไม่มีระบบ Inventory** | บันทึกได้แค่ "ปิด/เปิดการขาย" manual — ไม่มี Stock count อัตโนมัติ |
| **ไม่มี Bundle / Combo** | ขายเซ็ตคู่ทำไม่ได้ — ต้องสร้างเมนูใหม่หรือใช้ Discount manual |
| **Option ไม่มีต้นทุน auto-calculate** | ถ้าตัวเลือก "เพิ่มไข่ดาว" → ต้องกรอก CostPrice เอง |
| **ลบหมวดที่มีเมนู ทำไม่ได้** | ต้องย้ายเมนูไปหมวดอื่นก่อน → เพิ่มขั้นตอน |
| **Tags มี 3 ตัวเท่านั้น** | EMenuTag enum: Recommended/Seasonal/SlowPreparation — ไม่รองรับ tag แบบ "เผ็ด/เย็น/ร้อน" หรือ "BestSeller" เพิ่ม tag ใหม่ต้องแก้ enum |
| **IsPinned ไม่ Auto-Sort** | ระบบเก็บ flag แต่ MenuService ไม่ได้ order by IsPinned — ต้อง implement ฝั่ง Frontend |
| **ไม่มี Multi-language เกินไทย-อังกฤษ** | ร้านที่ขายต่างชาติเยอะ (จีน/ญี่ปุ่น) → ต้องเพิ่มภาษาที่ระดับ schema |

## 7. ความสัมพันธ์กับ Module อื่น

### Module นี้ส่งข้อมูลไปให้ใคร

| Module ปลายทาง | ส่งอะไรไป | ใช้ทำอะไร |
| --- | --- | --- |
| **Order** | MenuId + ชื่อ + ราคา + Options ที่เลือกได้ | สร้าง OrderItem (พร้อม snapshot ราคา) |
| **Self-Order (Customer)** | Menu + Option Group ที่เปิดขายและในช่วงเวลาปัจจุบัน | แสดงในหน้า Mobile Web ลูกค้า |
| **Kitchen Display** | ชื่อเมนู + CategoryType + Options ที่ลูกค้าเลือก | แยกแสดงตามสถานี (อาหาร/เครื่องดื่ม/ของหวาน) |
| **Dashboard** | MenuId + ชื่อ + จำนวนที่ขาย | คำนวณ Top Selling |
| **Payment** | ชื่อเมนู + ราคา | แสดงในใบเสร็จ |

### Module นี้ดึงข้อมูลจากใคร

| Module ต้นทาง | ดึงอะไรมา | ใช้ทำอะไร |
| --- | --- | --- |
| **Authorization** | สิทธิ์ของ Position | ตรวจว่าใครแก้ Menu แต่ละประเภทได้ |
| **Admin (File)** | FileId | เก็บอ้างอิงรูปเมนู |
| **Admin (ShopSettings)** | เวลาทำการ (Operating Hours) | กำหนดว่าเมนูช่วงไหนเปิดขาย (Period 1 / 2) |

## 8. สรุปสำหรับรายงาน (1 ย่อหน้า)

> Module Menu เป็นระบบจัดการรายการสินค้า (เมนูอาหาร) ของร้าน ที่แบ่งโครงสร้าง 3 ระดับ คือ Category Type (อาหาร/เครื่องดื่ม/ของหวาน) → Sub Category (หมวดหมู่ย่อยที่กำหนดเอง) → Menu Item โดยแต่ละเมนูสามารถผูกกับ Option Group (กลุ่มตัวเลือกเสริม) แบบหลายต่อหลายเพื่อให้ลูกค้าเลือกความเผ็ด ความหวาน หรือท็อปปิ้งได้ ระบบรองรับการกำหนดราคาขายและต้นทุนแยก ทำให้คำนวณกำไรขั้นต้นผ่าน Dashboard ได้ พร้อมฟีเจอร์เสริมที่สำคัญต่อร้านอาหารยุคใหม่ ได้แก่ การกำหนดช่วงเวลาขาย (Period 1/2) ตามเวลาทำการของร้าน การแจ้งสารก่อภูมิแพ้ การปักหมุดเมนูแนะนำ และระบบ Tags แบบ bit flags ที่ทำให้เมนูหนึ่งจำแนกได้หลายลักษณะพร้อมกัน นอกจากนี้ราคาเมนูที่ถูกสั่งจะถูก snapshot ลงในออเดอร์ ทำให้การเปลี่ยนราคาในอนาคตไม่กระทบกับออเดอร์เก่า รักษาความถูกต้องของข้อมูลการขายในอดีต
