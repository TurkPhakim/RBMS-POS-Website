## ตารางเปรียบเทียบ RBMS-POS กับต้นฉบับทั้ง 2

### ความเหมือนของ RBMS-POS กับต้นฉบับที่ 2

| ประเด็น | ต้นฉบับ 2 (E-Commerce IT) | RBMS-POS |
|---------|---------------------------|----------|
| **โดเมน** | ระบบขายสินค้า (B2C) | ระบบขายอาหาร (POS) |
| **กลุ่มผู้ใช้** | Customer + Admin | Customer + Staff + Admin |
| **มี Order/Cart** | มี (Shopping Cart → Order) | มี (Order → Bill → Payment) |
| **มีระบบชำระเงิน** | Omise + โอนแนบสลิป | Cash + QR + Slip Verification |
| **มี State** | Order Status (Pending → Shipped → Delivered) | OrderItem State Machine 7 สถานะ |
| **Database Schema** | 19 ตาราง | 37 Entity (37 Table หลัก) |

### ความต่างที่สำคัญ

| ประเด็น | ต้นฉบับ 2 | RBMS-POS |
|---------|-----------|----------|
| **Real-time** | ไม่มี (Refresh manual) | มี SignalR (Kitchen Display, Notifications) |
| **Mobile Self-Service** | ไม่มี | มี (Mobile Web — Customer Self-Order via QR) |
| **OCR Slip** | แอดมินตรวจมือ | OCR Auto + Manual Fallback |
| **Authentication** | Session-based | JWT + Refresh Token + BCrypt |
| **Tech Stack** | PHP + MySQL + jQuery | C#/.NET 9 + Angular 19.1 + SQL Server |
| **Architecture** | Server-rendered (MPA) | API + SPA (n-Tier) |
| **จำนวน Flowchart** | 15 (ละเอียดทุกระบบ) | เสนอ 10 (ครอบคลุม 8 Module) |
| **จำนวน Module** | 1 ระบบรวม | 8 Business Modules |

### ผลกระทบต่อการเขียนรายงาน

1. **ใช้โครงสร้างบทที่ 3 ของต้นฉบับ 2 เป็นแม่แบบหลัก** (Architecture → Use Case → ภาพรวม → Flowchart → UI Mockup → ER + Data Dictionary)
2. **ใช้ Test Case Table ของต้นฉบับ 2 เป็นมาตรฐาน** (รหัส + สิ่งที่ทดสอบ + คาดหวัง + ได้จริง + สรุปผล รัน 3 ครั้ง)
3. **เพิ่มหัวข้อ 1.3 สมมติฐาน** ใน RBMS-POS (ตัวอย่าง 1 ไม่มี แต่ตัวอย่าง 2 มี)
4. **แยกหัวข้อ 5.2 ปัญหา และ 5.3 วิธีแก้** ตามตัวอย่าง 2
5. **เพิ่มหัวข้อ 3.1 System Architecture, 3.2 Use Case, 3.6 UX/UI** ที่ตัวอย่าง 1 ไม่มี
6. **บท 2 ต้องเพิ่มทฤษฎี Domain-specific** ไม่ใช่แค่ Tech Stack — เช่น "ระบบ POS ในอุตสาหกรรมร้านอาหาร", "Real-time Communication"
